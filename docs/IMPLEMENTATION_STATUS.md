## What the account implementation enforces

PostgreSQL derives the user from the session, validates full assigned-chapter completion, and owns XP and achievement changes. Per-user locks and unique activity keys protect rewards from duplicate requests. Reflections and other personal tables retain owner-only reads; direct client writes and private quiz answers are restricted. The journey API verifies the user and active Auth session, validates bounded commands and Origin, and returns private/no-store responses.

The account provider does not persist journals/progress in localStorage, automatically import demo records, or fall back to the demo after an account error. A user can explicitly preview and merge a backup; server validation and reward derivation apply. Quiz feedback becomes available after submission. Embedded PostgreSQL tests execute the actual migrations with two synthetic identities; SDK/session boundary tests use mocks and are not evidence of hosted OAuth or renewal.
