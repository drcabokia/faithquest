## Security model

The server verifies identity and an active Auth session on every journey API request. PostgreSQL independently derives the actor from `auth.uid()`; command signatures accept no user ID, XP amount, completion date, or unlocked badge. Per-user row locks and unique reward keys serialize/reject duplicates. Day completion requires all assigned chapters. Private quiz solutions are read only by the trusted function. Personal tables retain RLS for direct reads; helper execution is revoked from client roles. Mutation requests require the configured Origin, bounded JSON bodies, and strict Zod validation. Database error details are not returned to browsers. Auth/data responses are not shared-cacheable.

Current implementation guidance: [Supabase SSR clients](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs&package-manager=npm), [Google sign-in](https://supabase.com/docs/guides/auth/social-login/auth-google).

| Category                   | Per-account fixed-window allowance | Where enforced                                                                 |
| -------------------------- | ---------------------------------- | ------------------------------------------------------------------------------ |
| Journey snapshots          | 180 per minute                     | Public `get_journey`, including snapshots returned from commands               |
| Journey commands           | 60 per minute                      | All six write RPC wrappers, including initialize and idempotent repeats        |
| Account export             | 6 per five minutes                 | Verified export route admission before reading/downloading                     |
| Eligible deletion attempts | 3 per fifteen minutes              | Edge handler after verified current session/recent OAuth and before revocation |
| Account connection checks  | 6 per minute                       | Verified connection endpoint                                                   |
